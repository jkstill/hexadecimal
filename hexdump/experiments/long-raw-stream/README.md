# LONG RAW stream experiments

Neither prototype passed client fetch testing. Both are excluded from the package install.

On Oracle 19.12, the internal JDBC driver read BINARY_TEST.MY_LONG_RAW in 8192-byte chunks within a single Java invocation. The SHA-256 hashes matched the input pattern generated by blob-load.pl.

| Fixture | Bytes | SHA-256 |
| --- | ---: | --- |
| LONG RAW | 129 | 5099c6a56203f9687f7d33f4bfdf576d31dc91f6b695ecea38b2770c87631135 |
| VERY LONG RAW | 1161000 | 295032f28a2307c588b80bef4b94248dacdf7f26db99292f8c2662eab88ab659 |

The 19c iterator used ODCITableStart, ODCITableFetch and ODCITableClose. A full server-side count returned 72564 rows for VERY LONG RAW (one header and 72563 data lines). Fetching formatted rows through DBD::Oracle verified the null, 1-, 16- and 17-byte cases before the server process disconnected. The alert log recorded ORA-07445, incident 521270 on cdb2.

The earlier 26ai prototype also passed a server-side count on a 57339-byte value and lost the server process during client fetch. An aggregate count alone does not validate a pipelined dump. The underlying cause, memory scaling and early termination behavior remain unverified.

On ATP 23.26.4.1.0 with JAVAVM enabled, a server-side PL/SQL cursor loop checked every address, hex field and printable-text field from the ODCI iterator against a repeating 00 to FF pattern. All ten fixtures passed (NULL, 1, 16, 17, 1999, 2000, 2001, 32767, 32768 and 2097153 bytes). SQL*Plus using the 21c client also fetched the header and both data lines of the 17-byte value. Direct multi-fetch client consumption of a large value remains unverified on ATP.

On the same ATP service, the Oracle 21c client Perl 5.38.2 loaded its bundled DBI 1.644 and DBD::Oracle 1.90. Direct fetches passed for no match, NULL, and values of 1, 16 and 17 bytes. For each larger value, the client requested one source row and sorted the dump output on the server by descending address before fetching. Perl verified the address, hex and text of every line and the SHA-256 of the reassembled bytes. The largest result contained 131073 data lines and 2097153 bytes. This checks the bundled driver with large sorted results. The unsorted multi-row pipeline and early-termination cases from the original regression remain untested on ATP.
